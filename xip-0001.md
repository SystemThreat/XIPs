## Abstract

An xCoin Improvement Proposal (XIP) is a design document: one numbered,
public, immutable-once-final record of a decision about the xCoin network.
This XIP defines what XIPs are, the kinds that exist, how one becomes real,
and who decides — including the honest part about who decides today.

## Motivation

Decisions about a young network happen fast and informally. That is fine —
until strangers depend on them. The first independent node not run by the
founder joined the rehearsal network in September 2026; from that moment,
"the founder remembers deciding" is no longer a record. XIPs make every
decision citable, datable, and arguable-with before mainnet genesis
(September 30, 2026) makes some of them permanent.

## The four types

The type answers the most common governance question — "is this a fork?" —
before anyone has to ask it.

**Consensus.** Changes what makes a block or transaction valid. The only
type that can fork the chain. Tightening validity is a soft fork; loosening
it is a hard fork; either way the XIP must say which, and how it activates.
Examples: witness discipline, subsidy schedule, difficulty rules.

**Policy.** Changes the default behavior of official xCoin software without
touching validity. Cannot fork the chain; a node that never heard of it stays
in perfect consensus. Example: XIP-2, the own-node pool rule.

**Process.** Changes how the project itself works. Example: this document.

**Informational.** Records a design as it already exists, so the record is
complete. Carries no new obligation.

## Statuses

`Draft → Discussion → Accepted → Active`, with exits to `Rejected`,
`Withdrawn`, or `Superseded (by XIP-n)`. Consensus XIPs have one more step:
`Deployed`, reached only when the activation condition in the XIP itself has
been met on the chain it names. Nothing Final is ever edited except its
status line; corrections come as a new XIP that supersedes it.

## How to propose

1. Write the XIP using `xip-template.md`. Real content over ceremony: an
   abstract a stranger can follow, a specification an implementer can build
   from, and the honest security considerations.
2. Post it for discussion on **minedifferent.com/c/protocol**. Forum
   identity is an ML-DSA-65 signature, so every voice in an xCoin governance
   discussion is post-quantum-authenticated — argument and identity carry
   the same cryptography as the chain.
3. Open a pull request against the XIPs repository. The editor assigns the
   number when the draft is coherent (numbers are cheap; endorsement is not
   implied by having one).

## Who decides

Today: the founder is the sole editor and the final word, because today the
founder operates the majority of the network and signs its releases. That is
stated plainly rather than dressed up. Two commitments temper it:

- **Everything in public.** No decision counts as made until its XIP is
  merged; discussion happens where anyone — including anonymous guests —
  can read it.
- **The process must outgrow its founder.** When independent node operators,
  miners, and implementers exist in meaningful numbers, this XIP is to be
  superseded by one that distributes editorship and defines activation by
  signaling rather than decree. Consensus XIPs after mainnet genesis should
  expect miner/node signaling; before genesis, a flag-day at genesis is
  legitimate and every rule ships tested on testnet A first.

## Activation of Consensus XIPs

Each Consensus XIP must name its chain(s), its activation mechanism
(genesis rule, flag height, or signaling), and its rehearsal: no consensus
change reaches mainnet without having run on a testnet. Until mainnet
genesis, mainnet consensus XIPs may activate at genesis itself — the
cheapest, cleanest fork there will ever be is the one at block 0.

## Security considerations

A governance process is an attack surface: social pressure, fake urgency,
and ambiguity are its exploits. The mitigations here are smallness (four
types, one ladder), publicity (no private acceptance), and the type system
itself (nothing labeled Policy or Process can be smuggled into validity).
