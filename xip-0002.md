## Abstract

The official xCoin pool software refuses to start unless its node RPC
endpoint is literal loopback: to run a pool, you run a full node on the same
machine. Every pool is thereby one more independent verifier of the chain.

## Motivation

Pools concentrate; nodes verify. A pool that leans on someone else's node
adds hashpower routing without adding verification — the parasitic shape
that hollowed out other networks. Binding the two means pool growth IS node
growth: organic, verifying, geographically real. The rule applies to
testnet A and to mainnet from genesis (September 30, 2026).

## Specification

At startup, before credentials are read, `xcoin-pool` resolves
`XCOIN_RPC_HOST` and exits with a stated refusal unless the value is a
literal loopback address (`127.0.0.0/8`, `::1`) or the string `localhost`.
A hostname that merely resolves to loopback is refused: no legitimate
configuration needs one, and accepting it invites evasion. On success the
pool logs: `own-node rule satisfied: RPC on loopback — this pool stands on
its own verifier`.

## Rationale for being Policy, not Consensus

A block mined through a rule-breaking pool is valid; no node can tell which
pool software produced it. The chain stays neutral. The rule's force is
normative — the official software encodes the culture — and its enforcement
is honest about that: anyone may fork the pool and strip the check, and in
doing so announces exactly what kind of operator they are.

## Backwards compatibility

None affected. Miners see no change; existing compliant deployments
(node and pool co-resident) start unchanged.

## Reference implementation

`xcoin-pool.py`, `require_own_node()` — deployed on the rehearsal pool
2026-09-23.

## Security considerations

The check reads an environment variable on the pool operator's own machine;
it defends a norm, not a key. It cannot be bypassed *accidentally*, which
is the design goal: violating it must be a deliberate, visible choice.
